# Meerkat Workshop - Hackathon Plan 2 (UI/UX Shift)

## 1. 概要 (Overview)
現在の「Modern Metal Mills (金属工場)」のロジックと基本構造（環境を介した分散型意思決定）を完全に活かしつつ、見た目と体験を **「Star-Office-UIのような、ミーアキャットが可愛く働くイラストベースのUI」** に進化させるための追加・変更計画です。

## 2. 必要な変更点・追加要素 (What to Add/Change)

### A. ビジュアル・アセットの追加（イラスト化）
現在の無機質なDiv要素による色変化を、イラストとアニメーションに差し替えます。
- **背景マップ画像**: 「ミーアキャットの巣穴・ワークショップ（砂漠の地下基地など）」の1枚絵（ピクセルアートや手描きイラスト）を追加。
- **キャラクター画像（スプライト）**: 5種類のエージェントをミーアキャットのキャラクターとして描き出し、状態ごとのGIFアニメーション（待機 `idle`、作業中 `working`、慌てる `panicked`、寝る `sleeping` など）を追加。

### B. エリアと役割の「ミーアキャット化」 (Theme Mapping)
現在の5エリアとエージェントの設定を、ミーアキャットの世界観にリダイレクトします。
1. **Furnace (炉)** -> **発掘場 / トンネル掘削 (Digging Zone)**
2. **Rolling (圧延)** -> **加工場 / 道具作り (Crafting Zone)**
3. **QC (品質管理)** -> **どんぐり・資材の検品所 (Inspection)**
4. **Warehouse (倉庫)** -> **食料・資材庫 (Storage)**
5. **Energy (電力)** -> **休憩所 / 食堂 (Rest Area)**

### C. 状態の可視化方法の変更 (Star-Officeライクな表現)
- **現状**: エリアの背景色が赤や緑に変わる、リスク値ゲージが伸びる。
- **追加**:
  - キャラクターの**アニメーション変化**（例：検品所でエラーが起きると、ミーアキャットが「ジタバタ」する）。
  - **吹き出し（Speech Bubbles）**: 各エージェント（ミーアキャット）が support / attack のシグナルを出したとき、ただ数字が動くのではなく、マップ上のキャラクターから「手伝うよ！」「ちょっと待って！」といった吹き出しを出し、Star-Office-UI のようなキャラ同士が非同期に会話し合っているような体験を作ります。

## 3. 実装上の追加タスク (Technical Additions)
このUIを実現するために、現在のMVPコードベースに以下の機能を加えます。

### フロントエンドの拡張
1. **Absolute Positioning System**: 1枚絵の背景画像に対して、特定のx/y座標（各エリア）にミーアキャットや施設の状態アイコンを絶対配置するレイアウトシステム。
2. **Sprite / GIF Animation Component**: ミーアキャットの現在の状態（`idle`, `working`, `alert`）を受け取り、対応するアニメーションを表示するReactコンポーネント。
3. **Bubble Manager (吹き出し制御)**: シグナルが発生した際に、キャラクターの上に一時的にメッセージを表示し、時間経過でフェードアウト（Evaporate）する仕組み。

### データモデルの微修正
- `Agent` データに、現在表示している「アニメーション状態（`animState`）」を持たせます。
- `Event` 発生時やシグナル蓄積時に、数値の計算だけでなく、各エリアのミーアキャットのアニメーション状態をトリガーするルーティングを追加します。

## 4. プロダクトの新しい見え方 (New Demo Story)
1. **通常稼働**: 5匹のミーアキャットがそれぞれの持ち場でトコトコ動いたり、居眠りしたりしている。
2. **イベント発生**: 観客が「特急注文（rush order）」ボタンを押す。
3. **シグナル発信**: 資材庫のミーアキャットが慌てたアニメーションに変わり、「急げ！」という吹き出しを出す。すると他のエリアのミーアキャットも連動して「手伝う（support）！」と吹き出しを出し始める。
4. **意思決定**: supportシグナルが閾値を超えると「決定」となり、工場全体が「クラフト集中モード」に切り替わり、ミーアキャットたちが全力で働き始める。

---
## 結論
コアとなる「状態管理と分散処理のロジック」は変える必要はありません。「数値を色にマッピングするコンポーネント」を、**「数値をGIFアニメーションと吹き出しにマッピングする絶対配置コンポーネント」に差し替える**だけで、目的のStar-Office-UIのような体験を作ることができます。

## 5. 実際の作業工程 (Action Plan & Build Tasks)

ここからは、実際にこの「ミーアキャット・ワークショップ」を作り上げるための具体的な作業手順です。現在の MVP(Plan 1) の上にどう構築するかをステップ化します。

### Step 1: デザイン & アセット準備 (Design & Assets)
1. **背景画像の作成/調達**:
   - ミーアキャットの巣穴（5つの機能エリア）を描いた1枚絵（ピクセルアート等）を用意する。
   - 例: 左上に「発掘場」、右上に「加工場」、中央に「検品所」など。
2. **ミーアキャットのアニメーション作成/調達**:
   - 状態ごとのスプライトシートまたはGIFを作成・用意する。
   - 必要な状態例: `idle` (待機/うろうろ)、`working` (作業中)、`panicked` (慌てる/エラー)。
3. **アセットの配置座標（Map Data）の定義**:
   - 背景画像に対して、各エリアの中心座標 (x, y) や、エージェントを配置する絶対座標のマッピングデータ (`constants/mapPositions.ts` など) を作成する。

### Step 2: UI基礎コンポーネントの実装 (UI Components)
1. **Canvas / Absolute Layer の実装**:
   - 背景画像を表示し、その上に絶対座標 (`position: absolute`) でキャラクターを配置できる基盤となるコンポーネント (`WorkshopMap.tsx`) を作成する。
2. **Character コンポーネントの実装**:
   - 状態 (`idle`, `working`, `panicked`) を受け取り、対応するGIFを切り替えて表示する `MeerkatAgent.tsx` を作成する。
3. **Bubble (吹き出し) コンポーネントの実装**:
   - `signal` (support/attack) が発生した際に、キャラクターの頭上にテキスト (例:「急げ！」「手伝うよ！」) を一時的に表示し、CSSアニメーション等でフェードアウトさせる `SpeechBubble.tsx` を実装する。

### Step 3: ロジックの組み込み・紐付け (Logic Integration)
1. **状態管理プロセスの流用**:
   - 既存の「Modern Metal Mills」で作ったデータモデル (`FactoryArea`, `Agent`, `Signal` の仕組み) を React の `useState` やカスタムフックで管理する。
2. **イベントと状態アニメーションの連動**:
   - エリアの `load` や `risk` が基準を超えたら、紐づく `Agent` の `animState` を `panicked` に変更するロジックを実装。
   - エージェントがシグナルを発行（support/attack判断）するタイミングで、吹き出しのキューにメッセージを追加する仕組みを作る。

### Step 4: ポリッシュと調整 (Polish & Tuning)
1. **アニメーションの遷移・自然さ調整**:
   - キャラクターの状態が切り替わるときの不自然さを減らす（例えば、極端な点滅を防ぐディレイ等を入れる）。
   - 吹き出しが重なりすぎないようにオフセットを調整する。
2. **デモシナリオを通した体験テスト**:
   - 画面下部のイベントボタン（「特急注文が入った!!」「発掘機が壊れた!!」など親しみやすい名前にする）を押し、波及していく吹き出しとアニメーションが視覚的にわかりやすく、Star-Office-UI のような「場」で生じる非同期のやり取りに見えるかテストする。
